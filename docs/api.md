# API Reference - Справочник API

Базовый адрес локального запуска:

```text
http://127.0.0.1:8080
```

Все ответы сервиса возвращаются в JSON.

Формат ошибки:

- `{"error":"..."}`

## Общие коды ответа

- `200` — успешный запрос
- `201` — объект создан
- `400` — неверные параметры или JSON
- `401` — ошибка аутентификации
- `403` — нет доступа
- `404` — сущность не найдена
- `409` — конфликт данных
- `500` — внутренняя ошибка сервера или БД

Время в полях `sent_at`, `last_message_at` возвращается строкой формата `DD.MM.YYYY HH24:MI:SS` в часовом поясе `Europe/Moscow`. Поля `created_at`/`updated_at` постов стены возвращаются как PostgreSQL `TIMESTAMPTZ` в текстовом виде.

## Auth - Аутентификация

### `POST /api/register`

Регистрирует нового пользователя.

Тело запроса:

- `login` — уникальный логин (1..50 символов)
- `password` — пароль (8..32 символов; минимум: 1 заглавная, 1 строчная, 1 цифра; без пробелов)
- `name` — отображаемое имя (2..100 символов)

Ответ `201`:

- `user_id`, `login`, `name`

Возможные коды ответа:

- `201` — пользователь создан
- `400` — невалидные поля или JSON
- `409` — логин уже занят
- `500` — ошибка БД

### `POST /api/login`

Выполняет вход.

Тело запроса:

- `login` — логин
- `password` — пароль

Ответ `200`:

- `user_id`, `login`, `name`

Возможные коды ответа:

- `200` — успешный вход
- `400` — невалидные поля или JSON
- `401` — неверный логин или пароль

## Users - Пользователи

### `GET /api/user/profile`

Возвращает профиль пользователя.

Параметры строки запроса:

- `user_id` — обязательный положительный `int`

Ответ `200`:

- `user_id`, `login`, `name`, `bio`

Возможные коды ответа:

- `200`, `400`, `404`, `500`

### `PATCH /api/user/profile`

Обновляет профиль или пароль.

Тело запроса:

- `user_id` — обязательный положительный `int`
- `name` — необязательная строка (2..100 символов)
- `bio` — необязательная строка (≤80 символов)
- `login` — необязательная строка (≤50 символов)
- `new_password` — необязательная строка (требования как при регистрации)
- `current_password` — обязателен, если меняется пароль

Особенности:

- должен быть передан хотя бы один обновляемый параметр: `name`, `bio`, `login`, `new_password`
- при смене пароля сервер проверяет текущий пароль

Ответ `200`:

- обновлённый `{ user_id, login, name, bio }`

Возможные коды ответа:

- `200`, `400`, `403` (неверный `current_password`), `404`, `409`, `500`

### `GET /api/users/search`

Поиск пользователей.

Параметры строки запроса:

- `query` — обязательная строка, минимум 2 символа

Поиск выполняется по полю `name` (`ILIKE`), результат ограничен 10 записями.

Ответ `200`:

- `query`, `count`, `users[]` (каждый: `user_id`, `login`, `name`)

Возможные коды ответа:

- `200`, `400`, `500`

## Chats - Чаты

### `GET /api/chats`

Возвращает список чатов пользователя.

Параметры строки запроса:

- `user_id` — обязательный положительный `int`
- `limit` — необязательный, по умолчанию `50`, диапазон `[1..200]`
- `offset` — необязательный, по умолчанию `0`, неотрицательный `int`

Ответ `200`:

- `user_id`, `limit`, `offset`, `total`, `has_more`
- `chats[]` — каждый элемент:
  - `chat_id`, `name`
  - `display_name` — отображаемое название (для private это имя собеседника)
  - `peer_user_id` — только для private
  - `last_message_at` — строка `DD.MM.YYYY HH24:MI:SS` или `""`
  - `unread_count`

Сортировка: по времени последнего сообщения убывание, затем по `chat_id` убывание.

Возможные коды ответа:

- `200`, `400`, `404`, `500`

### `POST /api/chats/group`

Создаёт групповой чат.

Тело запроса:

- `name` — название чата
- `creator_id` — положительный `int`
- `participants` — непустой массив положительных `user_id`

Особенности:

- создатель автоматически добавляется в участники, если его нет в массиве
- дубликаты в `participants` удаляются
- все указанные пользователи должны существовать

Ответ `201`:

- `chat_id`, `name`, `type_name = "group"`, `participants[]`

Возможные коды ответа:

- `201`, `400`, `500`

### `GET /api/chat/{chat_id}`

Возвращает информацию о чате и список участников.

Параметры пути:

- `chat_id` — обязательный положительный `int`

Параметры строки запроса:

- `user_id` — необязательный положительный `int`; если передан, сервер проверяет, что пользователь состоит в чате

Ответ `200`:

- `chat_id`, `name`
- `display_name` — для private — имя собеседника
- `type_name` — `"group"` или `"private"`
- `participants[]` — массив `{ user_id, name }`
- `participants_count`

Возможные коды ответа:

- `200`, `400`, `403`, `404`, `500`

### `PATCH /api/chat/{chat_id}`

Переименовывает групповой чат.

Тело запроса:

- `user_id` — ID пользователя, который делает запрос
- `name` — новое название

Ограничения:

- только для групповых чатов
- пользователь должен быть участником

Возможные коды ответа:

- `200`, `400`, `403`, `404`, `500`

### `POST /api/chat/{chat_id}/users/add`

Добавляет участника в групповой чат.

Тело запроса:

- `requester_id` — ID пользователя, который делает запрос
- `user_id` — ID добавляемого

Возможные коды ответа:

- `200`, `400`, `403`, `404`, `409`, `500`

### `POST /api/chat/{chat_id}/users/remove`

Удаляет участника из группового чата.

Тело запроса:

- `requester_id` — ID пользователя, который делает запрос
- `user_id` — ID удаляемого

Возможные коды ответа:

- `200`, `400` (включая попытку удалить себя), `403`, `404`, `500`

### `POST /api/chat/{chat_id}/leave`

Пользователь выходит из чата.

Тело запроса:

- `user_id` — ID пользователя

Возможные коды ответа:

- `200`, `400` (например, чат приватный), `404`, `500`

### `POST /api/chat/{chat_id}/typing`

Отмечает, что пользователь сейчас печатает (или перестал).

Тело запроса:

- `user_id` — положительный `int`
- `chat_id` — положительный `int` (также берётся из пути)
- `is_typing` — `bool`

Состояние хранится в `seagull_schema.typing_status` с `updated_at`. Считается «свежим» в течение 5 секунд.

Ответ `200`:

- `status: "ok"`, `chat_id`, `user_id`, `is_typing`

Возможные коды ответа:

- `200`, `400`, `403` (не участник чата), `404`

### `GET /api/chat/{chat_id}/typing`

Возвращает список пользователей, печатающих сейчас в чате (кроме самого запросчика).

Параметры строки запроса:

- `chat_id`, `user_id` — оба положительные

Считаются «печатающими»: записи в `typing_status` с `is_typing = TRUE` и `updated_at > NOW() - INTERVAL '5 seconds'`.

Ответ `200`:

- `chat_id`, `count`, `typing_users[]` — каждый `{ user_id, name }`

Возможные коды ответа:

- `200`, `400`, `403`

## Messages - Сообщения

### `POST /api/messages/send`

Отправляет сообщение.

Тело запроса:

- `sender_id` — положительный `int`
- `content` — непустой текст
- `chat_id` — неотрицательный `int`
- `receiver_id` — обязателен для личного чата (`chat_id = 0`)

Особенности:

- если `chat_id = 0`, сервис создаёт или использует существующий приватный чат между `sender_id` и `receiver_id`
- при `chat_id = 0` поле `receiver_id` должно быть положительным и не равно `sender_id`
- если `chat_id > 0`, отправитель должен быть участником чата

Ответ `201`:

- `message_id`, `sender_id`, `chat_id`, `content`, `sent_at`
- при создании нового приватного чата: `is_new_chat = true`, `receiver_id`

Возможные коды ответа:

- `201`, `400`, `403`, `404`, `500`

### `GET /api/messages`

Возвращает сообщения чата.

Параметры строки запроса:

- `chat_id` — обязательный неотрицательный `int`
- `user_id` — обязательный положительный `int`
- `limit` — по умолчанию `50`, диапазон `[1..200]`
- `offset` — по умолчанию `0`, неотрицательный `int`

Побочный эффект: при чтении этим эндпоинтом обновляется `chat_users.last_read_message_id` для пары `(chat_id, user_id)` до максимального `message_id` чата (если это число больше уже сохранённого).

Ответ `200`:

- `chat_id`, `limit`, `offset`
- `messages[]` — `{ message_id, content, sender_id, chat_id, sent_at }`

Возможные коды ответа:

- `200`, `400`, `403`

### `GET /api/messages/search`

Поиск сообщений (ILIKE по `content`).

Параметры строки запроса:

- `query` — минимум 2 символа
- `user_id` — обязательный положительный `int`
- `chat_id` — необязательный положительный `int`; если задан, поиск только в этом чате
- `limit` — по умолчанию `50`, диапазон `[1..200]`
- `offset` — по умолчанию `0`, неотрицательный `int`

Без `chat_id` поиск ведётся по всем чатам, в которых состоит `user_id`.

Возможные коды ответа:

- `200`, `400`, `403`, `500`

### `PATCH /api/messages/{message_id}`

Редактирует сообщение.

Тело запроса:

- `user_id` — ID автора
- `content` — новый непустой текст

Редактировать может только автор.

Возможные коды ответа:

- `200`, `400`, `403`, `404`, `500`

### `DELETE /api/messages/{message_id}`

Удаляет сообщение.

Тело запроса (или query) :

- `user_id` — ID автора

Удалять может только автор.

Возможные коды ответа:

- `200`, `400`, `403`, `404`, `500`

### `GET /api/messages/unread`

Сводка непрочитанных сообщений по всем чатам пользователя.

Параметры строки запроса:

- `user_id` — обязательный положительный `int`

«Непрочитанным» считается сообщение с `message_id > chat_users.last_read_message_id` (или просто >0, если поле NULL).

Ответ `200`:

- `user_id`, `total_unread`
- `chats[]` — `{ chat_id, chat_name, type_name, unread_count }`

Возможные коды ответа:

- `200`, `400`, `404`

### `POST /api/messages/read`

Помечает сообщения прочитанными.

Тело запроса:

- `user_id` — обязательный положительный `int`
- хотя бы одно из:
  - `message_id` — пометить конкретное сообщение прочитанным (и поднять `last_read_message_id` до `max(текущий, message_id)`)
  - `chat_id` — пометить весь чат прочитанным (поднять `last_read_message_id` до максимального `message_id` чата)

Дополнительно: в `messages.is_read = TRUE` ставится только для сообщений, у которых `sender_id != user_id` (свои сообщения не помечаются).

Ответ `200`:

- `status: "success"`, `user_id`, опционально `chat_id`, `message_id`

Возможные коды ответа:

- `200`, `400`, `403`, `404`

## Wall - Стена пользователя

### `POST /api/wall/{user_id}/post`

Создаёт пост на стене указанного пользователя.

Параметры пути:

- `user_id` — `wall_owner_id`, владелец стены

Тело запроса:

- `author_id` — положительный `int`
- `content` — непустой текст, максимум 1000 символов

Особенности:

- `author_id` и `wall_owner_id` могут совпадать (пост на свою же стену)
- оба пользователя должны существовать

Ответ `201`:

- `post_id`, `wall_owner_id`, `author_id`, `author_name`, `content`, `created_at`

Возможные коды ответа:

- `201`, `400`, `404`, `500`

### `GET /api/wall/{user_id}/posts`

Возвращает посты со стены пользователя.

Параметры пути:

- `user_id` — `wall_owner_id`

Параметры строки запроса:

- `limit` — по умолчанию `50`, диапазон `[1..200]`
- `offset` — по умолчанию `0`, неотрицательный `int`

Удалённые посты (`is_deleted = true`) не возвращаются. Сортировка: `created_at DESC`.

Ответ `200`:

- `wall_owner_id`, `wall_owner_name`, `limit`, `offset`, `count`
- `posts[]` — `{ post_id, content, author_id, author_name, created_at, updated_at }`

Возможные коды ответа:

- `200`, `400`, `404`, `500`

### `DELETE /api/wall/post/{post_id}`

Удаляет пост стены (soft delete: `is_deleted = true`).

`user_id` (он же `requester_id`) можно передать любым из способов: query-параметр `?user_id=`, поле `user_id` в JSON-теле или поле `requester_id` в JSON-теле.

Удалять может либо автор поста, либо владелец стены.

Ответ `200`:

- `post_id`, `deleted: true`, `message`

Возможные коды ответа:

- `200`, `400`, `403`, `404` (включая «уже удалён»), `500`
